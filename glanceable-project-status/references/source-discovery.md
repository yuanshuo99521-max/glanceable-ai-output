# 状态源发现与覆盖规则

## 目的

在授权边界内回答两个不同问题：

1. 当前项目的真实状态是什么。
2. 本次是否已经检查了项目声明的全部相关状态位置。

不要把第二个问题的未知隐藏在第一个问题的流畅总结中。

## 第一步：固定检查边界

- 优先使用用户给出的准确项目路径。
- 未给路径时，只能把当前工作目录当作候选根；先验证，不假定它是项目。
- 解析为绝对路径并确认存在。
- 记录允许读取的根目录、显式外部位置和禁止越界范围。
- 不搜索整个用户目录、磁盘或无关项目来猜测目标。
- 内部可以使用解析后的路径执行检查；用户报告默认改写为项目相对路径或功能标签。

## 第二步：确认项目和 Git 边界

在 Windows 环境中使用只读检查：

```powershell
git -C <project-root> rev-parse --show-toplevel
git -C <project-root> status --short --branch
git -C <project-root> branch --show-current
git -C <project-root> log -1 --format="%H %cI %s"
```

规则：

- `rev-parse` 失败就写明“该目录未绑定 Git 仓库”，不要伪造分支或 HEAD。
- dirty worktree 是事实，不是自动错误；现有改动默认属于用户。
- 工作树、分支、提交和远程状态是不同维度，不相互替代。

## 第三步：读取项目自己的规则入口

优先寻找并遵循项目显式规则入口：

- 从项目根到目标文件路径上适用的 `AGENTS.md`。
- 项目内 `.agents/`、`.codex/` 或项目文档声明的规则。
- manifest、workspace 配置、状态所有者说明或入口文档。

如果项目已声明 Canonical owner、ledger 或状态优先级，以项目规则为准。本参考不建立跨项目通用 Canonical 文件名。

## 第四步：建立候选状态源清单

只有在项目规则没有直接给出状态所有者时，才在项目根内进行有界候选发现。优先使用 `rg --files`，按名称寻找：

- status、state、ledger、checkpoint、workflow、manifest。
- agent、node、task、run、result、acceptance、verification。
- 项目明确使用的等价名称。

候选文件名不等于权威来源。对每个候选记录：

- 路径和对象类型。
- 项目规则是否声明它为所有者、投影、缓存、历史或候选。
- 更新时间和作用范围。
- 是否需要其他来源交叉验证。

## 第五步：检查机器状态类别

在项目实际存在时，至少判断以下类别是否适用：

- Git：HEAD、分支、工作树、相关变更。
- Gate 或验收条件：定义、结果、时间和影响。
- State 或账本：当前状态所有者、历史和候选投影。
- Agent：职责、活动证据、终态报告和验证结果。
- Node：流程位置、前置条件和后继动作。
- Artifact：存在、完整、技术验证、领域或业务接受。
- 测试和运行：退出状态、失败、警告、结果边界。
- 外部位置：项目配置显式声明的其他目录、服务或远程状态。

不适用的类别可以标为“不适用”，不得为了模板完整虚构来源。

## 第六步：处理外部状态位置

- 只跟随项目配置或用户明确给出的外部位置。
- 外部位置需要额外权限时，说明准确路径和用途，再按权限流程处理。
- 未获权限、位置不可达或未读取时，覆盖只能是 `PARTIAL`。
- 不从相似项目、全局 Skill 或个人记忆导入当前项目事实。

## 信息最小化

- 只读取形成当前项目判断所需的最小状态信息，不为完善报告而收集个人资料。
- 用户报告默认不展示姓名、用户名、邮箱、账号标识、用户目录前缀、主机名、网络地址或设备标识。
- 外部位置默认使用功能标签；只有当前操作确实需要且用户明确要求时，才显示经过确认的准确位置。
- 原始日志进入报告前必须移除个人标识、主机信息和凭据内容。
- 发现令牌、密钥、口令、会话凭据或疑似敏感值时，不读取或复述其值；只记录存在性、影响和安全处置需求。
- 最小披露不得删除会改变结论的权限缺口、来源冲突或证据限制。

## 来源覆盖状态

### `VERIFIED_WITHIN_DECLARED_SCOPE`

同时满足：

- 项目根和 Git 边界已验证。
- 项目规则和状态所有者已读取。
- 项目显式声明的外部状态位置已检查，或明确不适用。
- 已知来源冲突和时间边界已记录。

该标签只对本次声明范围有效，不表示整台设备已扫描。

### `PARTIAL`

任一条件成立：

- 已知状态源尚未读取。
- 项目声明的外部位置不可达或未获授权。
- 来源冲突尚未解除。
- 只能读取摘要、缓存或旧快照。

### `NOT_TESTED`

任一条件成立：

- 没有真实项目路径。
- 候选目录不是项目且没有状态源。
- 尚未执行来源发现。
- 只有用户提供且未独立核验的状态事实，不能验证真实来源覆盖。

## 内部覆盖清单

生成报告前维护以下最小记录：

```text
project_root:
git_boundary:
project_rules:
state_owner:
agent_sources:
node_sources:
artifact_sources:
test_or_acceptance_sources:
declared_external_sources:
unread_or_conflicting_sources:
coverage_status:
```

用户报告默认只展示影响判断的来源缺口和最小证据，不倾倒完整清单。
