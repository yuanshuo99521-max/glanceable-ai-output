# 一眼读懂项目状态

`Glanceable Project Status` 是一套把复杂机器状态转成人能迅速抓住重点的 Codex Skill。

它面向 Git、Gate、State、Artifact、Agent、Node、测试和日志等项目内部信息，把它们转换为清晰、可扫描、可判断、可继续行动的项目进度说明。

> 将大模型输出转为容易被人瞬间 get 到的项目状态 Skill。

[下载 v1.0.0 ZIP](dist/glanceable-project-status-v1.0.0.zip)

## 名称

- 中文名：**一眼读懂项目状态**
- 英文名：**Glanceable Project Status**
- Skill ID：`glanceable-project-status`
- 仓库名：`glanceable-project-status`

“Glanceable”强调读者不必先理解项目内部系统，也能在短时间内看出：已经做成了什么、现在有什么用、哪里有问题、是否被阻塞，以及接下来要做什么。

## 我们为什么做这个 Skill

项目系统通常使用一套适合机器维护的语言。Gate 表示检查关口，State 表示流程状态，Artifact 表示产物，Agent 和 Node 表示执行单元或流程节点。它们对于自动化很重要，但直接搬到汇报里，人往往仍然不知道项目究竟进展到了哪里。

大模型可以准确复述这些字段，却可能把“信息完整”误当成“人已经看懂”。一份报告即使包含大量路径、版本、状态值和检查结果，也不一定能让读者立即回答最关键的问题：

- 已经做成了什么？
- 现在能用来做什么？
- 当前问题会不会阻止项目继续？
- 下一步是谁都能理解并核验的动作吗？
- 结论依据是什么，证据强度到哪里为止？

因此，我们没有把目标设成“让 AI 少说一点”，也没有要求机械地把专业内容改写成浅白文字。真正的目标是建立一套稳定的表达转换层：保留事实和领域专业术语，同时把机器内部对象翻译成读者能够判断的项目意义。

## 核心思路

默认结构固定为：

```text
一句话总览 → 状态分类 → 当前问题或阻塞 → 下一步 → 必要依据
```

这是一种渐进式信息结构：第一层先帮助读者作出判断，第二层说明各项状态，最后才提供路径、版本、命令、日志和来源边界。读者可以在需要时继续向下读取，而不必先穿过技术细节。

Skill 遵循六条核心原则：

1. **先说成果与用途。** 优先说明已经形成的能力和它现在能解决的问题。
2. **保留领域术语。** 不删除决定结论的专业概念，只为项目内部术语补充最小语境。
3. **固定视觉语义。** 符号是稳定的视觉词典，不是装饰。
4. **区分不同证据层级。** 文件存在、技术检查通过、领域接受和项目完成不是同一件事。
5. **先核对来源再下结论。** 报告必须说明读取了哪些状态所有者，哪些位置未读或不可达。
6. **默认只读与最小披露。** Skill 不修改项目状态，也不展示与当前判断无关的私人信息。

## 固定视觉语义

| 符号 | 固定含义 |
|---|---|
| 📍 | 当前结论或所处位置 |
| 🎯 | 当前目标或判断标准 |
| ✅ | 已有证据支持的完成、确认或验证条件 |
| 🔄 | 存在当前活动证据的进行中事项 |
| ⏳ | 尚未启动或等待处理的事项 |
| ⚠️ | 会影响结果，但关键路径仍可继续的问题 |
| ⛔ | 阻止关键下一步的条件 |
| ❓ | 未知、来源冲突或尚待决策 |
| 💡 | 明确标注且具有决策价值的推论 |
| ➡️ | 可执行、可验证的下一步 |
| 🔎 | 关键来源、核对范围和证据边界 |

符号先绑定语义，再根据内容组合。没有内容的分类直接省略，不用空区块填满模板。

## 它如何理解项目状态

在读取真实项目时，Skill 不假定 Git 是唯一真相，也不把当前目录中的某个状态文件直接当成权威来源。它会在授权范围内识别：

- 项目规则与状态所有者；
- Git 工作区、当前分支和相关变更；
- Gate、State、Artifact、Agent、Node 等结构化状态；
- 测试结果、日志、交接记录和发布依据；
- 项目明确声明的外部状态位置；
- 来源之间的冲突、时间差和覆盖缺口。

来源覆盖被单独标记为 `VERIFIED_WITHIN_DECLARED_SCOPE`、`PARTIAL` 或 `NOT_TESTED`。它只描述本次核对范围，不代表项目完成度，也不声称扫描过整台设备。

## 面向不同读者

同一组事实可以有不同的信息密度，但不能有不同的事实结论。

- `compact`：只保留当前判断、关键状态、阻塞和下一步。
- `standard`：加入必要解释，使不了解项目内部系统的读者也能判断。
- `evidence`：进一步保留来源、版本、时间、命令和证据边界。

适配依据只包括读者对当前领域的熟悉度、阅读目的、时间预算和证据需求。Skill 不根据年龄、学历、职业或隐蔽行为建立读者画像。

## 能做什么

- 把机器项目状态转换成面向人的进度说明。
- 解释 Gate、State、Artifact、Agent、Node 对实际项目步骤的影响。
- 区分已完成、进行中、待处理、风险、阻塞和未知。
- 在来源冲突或证据不足时降低结论强度。
- 为新接手者、项目负责人和技术成员提供不同密度的同一事实视图。
- 给出单一、可执行、可验证的下一步。

## 不做什么

- 不写回 State、Gate、Ledger 或其他项目状态。
- 不运行工作流，不批准结果，不发布版本。
- 不把 Agent 停止、Node 前进、Artifact 存在或技术检查通过直接写成整体完成。
- 不扫描未授权目录、整块磁盘或无关项目。
- 不作为通用论文写作、通用文献总结或万能回答模板。

这套思路未来可以扩展到文献汇报和其他 AI 回答场景，但当前版本有意冻结在“项目状态解释”这一可验证边界内。先把一个问题做成稳定工具，再讨论更宽泛的人类可读回答范式。

## 安装

### 用户级安装

把完整的 `glanceable-project-status` Skill 文件夹复制到：

```text
%USERPROFILE%\.codex\skills\
```

安装后的入口应位于：

```text
%USERPROFILE%\.codex\skills\glanceable-project-status\SKILL.md
```

### 项目级安装

若只在一个项目使用，可把 Skill 文件夹放入该项目已经配置的 Skill 发现目录。采用 `.agents\skills` 约定时，入口位置为：

```text
<project-root>\.agents\skills\glanceable-project-status\SKILL.md
```

项目未声明 Skill 发现目录时，优先使用用户级安装。新安装后若当前任务没有发现它，请新建任务或重新打开 Codex 客户端再检查。

## 调用

显式调用标识：

```text
$glanceable-project-status
```

也允许隐式调用。请求涉及项目进度、阻塞、交接状态、下一步，或需要把机器状态解释成人类可读信息时，Codex 可以自动选择它。

调用时最好同时明确项目路径或状态快照、允许读取的范围、报告面向的读者、信息密度，以及是否需要保留技术证据。缺少真实项目路径时，Skill 只能转换用户已经提供的事实，不能声称全面检查了项目。

## 结构检查

Skill 附带一个 PowerShell 检查器，用于检查符号、区块顺序、空区块和部分中文结构规则：

```powershell
$skillPath = Join-Path $env:USERPROFILE '.codex\skills\glanceable-project-status'
powershell -NoProfile -ExecutionPolicy Bypass -File "$skillPath\scripts\lint-status-report.ps1" -Path <report-path>
```

结构检查通过只证明格式不变量成立，不证明报告事实、来源覆盖或用户理解已经通过验收。

## 隐私与安全

- 所有读取和输出都遵循最小披露原则。
- 安装 Skill 不会产生额外文件读取权限。
- 外部目录、远程主机、私人资料和网络来源仍需按当前环境单独授权。
- 状态不得从相似项目、全局记忆或未授权位置推断。
- 来源冲突必须如实呈现，不选择更乐观的结论。
- 令牌、密钥、口令、会话凭据和疑似敏感值不得进入报告。

## 设计成熟度

当前版本已冻结行为边界、符号语义、来源发现、读者适配、转换规则、输出密度和结构检查标准。它是一个可直接安装的 Skill，但仍应在不同类型的真实项目中持续观察读者是否能更快、更准确地作出判断。
