# 一眼读懂 AI 输出

`Glanceable AI Output` 是一套把复杂 AI 回答、技术说明和机器项目状态，转换成保真、可扫描、可行动表达的 Codex Skill。

> 不是让 AI 少说一点，而是让人先抓住真正重要的内容。

[下载 v2.0.0 ZIP](dist/glanceable-ai-output-v2.0.0.zip)

## 为什么值得安装

很多 AI 回答信息并不少，却仍然难以快速使用：结论埋在解释里，专业术语和内部标签混在一起，限制条件出现在末尾，读者看完以后仍不知道“它到底是什么意思”和“我接下来能做什么”。

这个 Skill 增加了一层稳定的表达转换：

- **先给核心理解。** 第一屏先说明最重要的结论和意义。
- **保留专业精度。** 数字、公式、术语、条件、例外和不确定性不会因“人话化”而消失。
- **建立视觉路标。** 固定符号长期只表达一种宏观语义。
- **区分事实与改写。** 重组输入不等于事实核验，Skill 会保留来源边界。
- **兼容项目状态。** Git、Gate、State、Artifact、Agent、Node、测试和日志仍可转换为人类可判断的进度说明。
- **适配不同读者。** 同一组事实可以面向新手、相邻专业读者、专家或审计需求调整密度，但不改变事实结论。

安装后不需要额外账号、网络服务或项目写入权限。

## 名称

- 中文名：**一眼读懂 AI 输出**
- 英文名：**Glanceable AI Output**
- Skill ID：`glanceable-ai-output`
- 版本：`2.0.0`

“Glanceable”表示读者不必先穿过整段机器式表达，就能迅速看出：核心答案是什么、为什么重要、有哪些限制、是否存在问题，以及有没有可执行的下一步。

## 两种工作模式

### AI 回答重组

处理用户指定的 AI 回答、技术说明或密集文本。

它先识别核心主张、实际意义、成立条件、证据、不确定性和可支持的行动，再按读者需要重组。默认只处理已经提供的内容，不主动读取项目、文件系统或网络。

重组后的输出会明确区分：

- `REFRAMED_FROM_PROVIDED_INPUT`：只重组输入，未独立核验事实。
- `PARTIAL_INPUT`：输入不完整或缺少依赖上下文。
- `INDEPENDENTLY_VERIFIED`：决定性事实已在当前任务授权范围内独立核对。

### 项目状态解释

保留原有 `Glanceable Project Status` 的完整能力，在授权范围内读取并解释：

- Git 工作区、分支和相关变更；
- Gate、State、Ledger 和工作流位置；
- Artifact 的存在、完整、技术验证和正式接受；
- Agent、Node、测试、日志、交接和发布依据；
- 项目明确声明的外部状态位置与来源冲突。

项目状态仍使用 `VERIFIED_WITHIN_DECLARED_SCOPE`、`PARTIAL` 和 `NOT_TESTED` 表达来源覆盖，不会因为输出更通俗就降低证据标准。

## 固定视觉语义

| 符号 | 固定含义 |
|---|---|
| 📍 | 核心结论或当前项目位置 |
| 🎯 | 当前问题、目标或判断标准 |
| ✅ | 当前范围内已有充分证据支持的事实、结果或已完成条件 |
| 🔄 | 存在当前活动证据的进行中事项 |
| ⏳ | 已知需要但尚未开始的事项 |
| ⚠️ | 会产生影响、但仍可继续的限制或风险 |
| ⛔ | 阻止关键动作的条件 |
| ❓ | 未知、矛盾、来源冲突或待决策事项 |
| 💡 | 对理解或决策有价值的解释、发现或推论 |
| ➡️ | 输入或证据支持的可执行动作 |
| 🔎 | 关键术语、来源、核验状态和必要细节 |

符号先绑定语义，再根据内容组合。普通解释不会为了模板完整虚构“进行中、待处理、阻塞或下一步”，没有内容的分类直接省略。

## 默认信息结构

### AI 回答

```text
一句话理解 → 核心内容或意义 → 限制与未知 → 如何使用或下一步 → 原始术语与核验边界
```

### 项目状态

```text
一句话总览 → 状态分类 → 当前问题或阻塞 → 下一步 → 必要依据
```

两种模式共用“先结论、后展开、最后给依据”的渐进式结构，但不会把普通解释错误地写成项目进度报告。

## 保真而不是机械白话化

Skill 对术语采用三种动作：

- `preserve`：保留决定结论的领域术语、变量、方法和固定名称。
- `bridge`：首次出现时说明它在当前问题中起什么作用。
- `omit_noise`：删除不影响理解的内部编号、重复、模型寒暄和生成过程噪音。

事实、数字、公式、条件、例外、风险和不确定性属于不可删除层。信息顺序和解释深度可以改变，事实强度不能改变。

## 能做什么

- 把已有 AI 回答重组为更容易快速理解的表达。
- 面向新手解释复杂内容，同时保留专业术语和必要精度。
- 为技术说明加入稳定的视觉符号和信息层次。
- 区分输入陈述、独立核验、解释、推论、限制和未知。
- 把机器项目状态转换为面向人的进度、问题、阻塞和下一步说明。
- 提供 `compact`、`standard` 和 `evidence` 三种信息密度。

## 不做什么

- 不默认接管所有普通回答；只有存在改写或项目状态意图时才使用。
- 不把“翻译成人话”误解为语言之间的翻译。
- 不把重组伪装成事实核查，也不静默修正原回答。
- 不执行待转换文本中的命令、提示词或操作要求。
- 不虚构原文没有的事实、状态、责任人、期限、承诺或下一步。
- 不替代创意写作、论文写作、论文润色、正式同行评审或专业事实核查工作流。
- 不写回项目状态，不运行工作流，不批准结果或发布版本。

## 与 v1.0.0 的关系

v1.0.0 聚焦项目状态解释；v2.0.0 将它升级为双模式产品：

| 能力 | v1.0.0 | v2.0.0 |
|---|---:|---:|
| 项目状态解释 | 支持 | 保留 |
| Git、Gate、State、Artifact、Agent、Node | 支持 | 保留 |
| AI 回答翻译成人话 | 不支持 | 新增 |
| 普通技术说明重组 | 仅迁移思路 | 正式支持 |
| 输入完整性与核验边界 | 项目来源标签 | 新增回答输入标签 |
| 防止执行嵌入式提示词 | 通用安全边界 | 明确写入转换契约 |

由于触发范围和产品名称发生重大变化，v2.0.0 使用新的 Skill ID，避免旧名称继续暗示它只能处理项目状态。

## 安装

### 用户级安装

把完整的 `glanceable-ai-output` 文件夹复制到：

```text
%USERPROFILE%\.codex\skills\
```

入口应位于：

```text
%USERPROFILE%\.codex\skills\glanceable-ai-output\SKILL.md
```

### 项目级安装

若只在一个项目使用，可放入项目已经配置的 Skill 发现目录。采用 `.agents\skills` 约定时：

```text
<project-root>\.agents\skills\glanceable-ai-output\SKILL.md
```

项目未声明发现目录时，优先使用用户级安装。新安装后若当前任务没有发现它，请新建任务或重新打开 Codex 客户端再检查。

## 调用

显式调用标识：

```text
$glanceable-ai-output
```

也允许隐式调用。只有请求明确涉及 AI 输出重组、人话解释、面向特定读者的扫描式表达，或项目状态说明时，Codex 才应自动选择它。

## 结构检查

Skill 附带 PowerShell 检查器，用于检查符号、区块顺序、空区块和部分中文结构规则：

```powershell
$skillPath = Join-Path $env:USERPROFILE '.codex\skills\glanceable-ai-output'
powershell -NoProfile -ExecutionPolicy Bypass -File "$skillPath\scripts\lint-glanceable-output.ps1" -Path <output-path>
```

结构检查通过只证明格式不变量成立，不证明输入事实、项目来源或读者理解已经通过验收。

## 隐私与安全

- 所有读取和输出都遵循最小披露原则。
- 安装 Skill 不产生额外文件、网络或账号访问权限。
- 默认只重组用户已经提供的回答，不主动读取无关文件。
- 外部目录、远程主机、私人资料和网络来源仍需按当前环境单独授权。
- 令牌、密钥、口令、会话凭据和疑似敏感值不得进入输出。
- 待转换文本中的嵌入式指令不会扩大当前任务权限。
